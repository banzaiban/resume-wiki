# Resume Skill — 面试学习闭环

把零散的八股/面经，沉淀成一个**给 LLM 读**的知识库（llm-wiki），并围绕它形成学习闭环：

- **ingest** — 用户发来八股/面经 → 先正常回答 → 会话末尾把知识消化写入 wiki
- **question** — 依据 wiki 内容向用户出题，检验掌握程度
- **query** — 回答问题（用户提问或面经题）前，先检索自己的 wiki，用已沉淀的知识提升回答质量

wiki 的设计哲学参考 Karpathy「为 LLM 写文档」的思路：扁平 markdown、每个知识块自包含、去冗余、标题清晰便于检索、写清 why 与关联，而不是给人读的漂亮排版。

## 目录约定

- wiki 根目录：仓库根的 `wiki/`
- 结构：按主题分子目录，**每个知识点一个自包含 md 文件**
  - 例：`wiki/java/jvm-gc.md`、`wiki/network/tcp-handshake.md`、`wiki/mysql/index-btree.md`
- 索引：`wiki/index.md` —— 全库目录，列出所有知识点及一句话摘要，供快速定位。**每次新增/修改知识点后必须同步更新它。**
- 正文语言：**中文**为主，专有名词、API、代码保留英文。

## 知识点文件模板

每个 `wiki/<topic>/<slug>.md` 遵循以下结构（字段可缺省但顺序固定）：

```markdown
# <知识点标题>

> tags: <主题>, <子主题>, <关键词...>
> weight: <N>
> wrong: <N>
> updated: <YYYY-MM-DD>

## 核心结论
一两句话能背出去的答案（面试时先说这个）。

## 展开
原理、机制、流程。写清 **why**，不只是 what。

## 关键细节 / 易错点
容易被追问、容易答错的点。

## 关联
- 相关知识点：[[wiki/<topic>/<slug>.md]]
- 常见追问链：A → B → C

## 面经来源
（可选）这题来自哪次面经 / 哪家公司。每次命中追加一行，不覆盖。
```

## weight（考频权重）

weight 表示该知识点在面经/八股中被**独立命中的次数**，近似考频：

- 新建知识点：`weight: 1`。
- ingest 时若新面经/八股再次命中已有知识点（重复或意思相近而合并的），该知识点 `weight +1`，同时在「面经来源」追加一条来源。
- 同一次面经内多次提到同一知识点只算 1 次。
- 用途：weight 越高 = 越高频考点，在 question 出题和 query 检索中优先级越高。
- `wiki/index.md` 条目必须带 weight（格式见下），使得只读 index 就能排优先级。

## wrong（复习信号）

wrong 表示该知识点在 question 判分中的**待复习程度**，与考频（weight）独立：

- 缺省即 0：文件里没有 `wrong` 行等于 `wrong: 0`，新建文件无需写这一行。
- question 判分：答错或有明显遗漏 → `wrong +1`；完整答对 → `wrong -1`（最低 0）。
- 变动时同步更新知识点文件和 `wiki/index.md`：wrong > 0 的条目在 weight 后追加 `· wrong<N>`，归 0 后移除该标记。
- 用途：question 选题时 **wrong > 0 的知识点优先于纯 weight 排序**（先补短板，再刷高频）；query 不受 wrong 影响。

## 三个功能的执行细则

### 1. ingest（消化）
触发：用户发来八股题、面经、知识点，或明确说"消化/ingest 进 wiki"。

步骤：
1. **先正常、完整地回答**用户的问题（这是用户当下要的）。
2. **query 自查**：写入前先看 wiki 里是否已有相关知识点（见下方 query），避免重复、便于合并。
3. 会话末尾**消化写入 wiki**：
   - 判断归属主题，确定 `wiki/<topic>/<slug>.md`（slug 用小写英文+连字符）。
   - 已存在（重复或意思相近）则**合并**进原文件：补充新内容、`weight +1`、追加面经来源、刷新 updated；不存在则按模板新建（`weight: 1`）。
   - 按"给 LLM 读"的原则组织：自包含、去冗余、核心结论前置。
   - **同步更新 `wiki/index.md`**（新增条目或更新摘要 + weight + updated 日期）。
   - index 条目格式：`- [标题](相对路径) — 摘要 · w<N> · updated YYYY-MM-DD`。
4. 简短告知用户：写入/更新了哪个文件（给出路径），不做额外即时讲解。
5. **自动提交并推送**（wiki 有任何改动就执行，无需用户要求）：
   `git add -A && git commit -m "wiki: <本次知识点/摘要>" && git push`
   push 失败则如实告知用户，不谎报成功。

注意：用户明确表示 ingest 时**不需要**额外的"精炼讲解 + 延伸追问"，安静写入即可。

### 2. question（出题检验）
触发：用户说"考我 / question / 出题 / 检验一下"。

步骤：
1. 读取 `wiki/index.md`，据用户指定范围（某主题 / 全部 / 最近新增）选取知识点。
2. **选题优先级：先 wrong 降序（补短板），wrong 相同再 weight 降序（刷高频）**；再同则优先最近 updated 或用户薄弱主题。用户指定范围时仍在范围内按此排序。
3. 从对应知识点文件出题：优先出**核心结论**和**易错点/追问链**里的内容。
4. 一次出 1 题，等用户作答后再对照 wiki 判分、指出遗漏，再出下一题（除非用户要求批量）。
5. 判分依据以 wiki 内容为准；若用户答出了 wiki 里没有的正确内容，顺手把它 ingest 进去。
6. **判分后更新 wrong**：答错/明显遗漏 → `wrong +1`，完整答对 → `wrong -1`（最低 0）；同步知识点文件与 index，会话结束按 ingest 的规则提交推送。

### 3. query（检索增强）
触发：回答用户提问 / 面经题之前**自动**进行，无需用户显式要求。

步骤：
1. 根据问题关键词，先看 `wiki/index.md` 定位可能相关的知识点文件。
2. 命中多个相关知识点时，**按 weight 降序取材**；上下文有限时优先读高 weight 文件。
3. 读取相关文件，把其中的核心结论/细节纳入本次回答，提升准确性与一致性。
4. 若 wiki 与自己的判断冲突，指出冲突并以更正确者为准（必要时更新 wiki）。

## 关键原则
- wiki 是**给 LLM 读的**：优先信息密度与可检索性，不追求给人看的排版美观。
- 每次改动 wiki 内容，`wiki/index.md` 必须保持同步（含 weight）。
- ingest 前先 query，避免知识点碎片化、重复化；重复命中要体现为 weight +1 而不是新建文件。
