# Graph RAG：相比向量检索的优势

> tags: rag, graph-rag, 知识图谱, 多跳推理, 实体关系
> weight: 1
> updated: 2026-08-04

## 核心结论
Graph RAG 把文档抽成实体-关系图谱，检索时沿边做多跳遍历；相比向量检索，优势在处理**复杂知识关联**：多跳问题（A 的供应商的产地）、跨文档关系推理、全局性总结（社区摘要）。代价是建图贵、更新难，生产上常与向量检索混用：向量召回入口实体 → 图谱扩展邻居。

## 展开
- **构建**：LLM 从 chunk 抽实体/关系三元组 → 入库（Neo4j 等图库）→ 可选社区聚类（Leiden）并为每个社区生成摘要（微软 GraphRAG 的路线，支撑"这批文档整体讲了什么"类全局问题）。
- **检索**：local search（从 query 实体出发遍历邻居）+ global search（社区摘要 map-reduce）。
- **vs 向量检索**：向量找"语义相似"，但相似 ≠ 关联——多跳链路中每一跳单独看都可能不相似；图谱显式存关系，多跳是图遍历而非多次模糊检索。向量胜在便宜、无需建图、模糊语义好。
- **混合用法**：向量召回拿到入口实体 → 图谱 BFS 扩展关联实体/关系 → 一并进上下文。图库多跳原理见数据库选型条目。

## 关键细节 / 易错点
- 追问"为什么向量检索处理不好多跳"：多跳问题的中间实体不出现在 query 里，语义相似度抓不住；需迭代检索或图谱。
- 追问"建图成本"：全量 LLM 抽三元组 token 开销大；增量更新时实体对齐/去重是难点。
