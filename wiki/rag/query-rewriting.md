# 查询改写 / 查询重写（含 HyDE 幻觉防护）

> tags: rag, query-rewriting, HyDE, 查询扩展, 指代消解
> weight: 2
> updated: 2026-08-04

## 核心结论
用户提问常常口语化、带指代、缺上下文，直接检索效果差。改写方法：结合对话历史做指代消解/补全、多跳问题拆子问题、同义/术语扩展、step-back（抽象一层再检索）、HyDE（让模型生成假设答案，用答案的向量去检索）。HyDE 防幻觉干扰：伪文档只用于检索不参与生成，与原始 query 双路召回融合，并在 prompt 中声明其可能有错。

## 展开
- **改写方法清单**：
  1. 指代消解/补全："它多少钱"→ 结合历史补全主语；
  2. 子问题分解：多跳/复合问题拆成可独立检索的子问题；
  3. 同义与术语扩展：口语词 → 领域术语（词典/LLM 改写）；
  4. step-back prompting：把具体问题抽象成上位问题先检索背景；
  5. HyDE：生成一篇"假想答案文档"，用它取向量检索——答案与真实文档的语义距离比问题更近。
- **HyDE 幻觉防护**（伪文档可能编造细节）：
  1. 伪文档只取向量用于召回，**不进生成上下文**，生成只依据真实召回文档；
  2. 双路召回：原 query 向量 + 伪文档向量各自召回再融合，单路幻觉不至于带偏全部结果；
  3. 生成侧不受伪文档影响，必要时可对伪文档降 temperature 或多采样取共识版；
  4. 召回后照旧过 reranker——伪文档召回的噪声会在精排被压下去。
- 改写模块要可观测：记录原 query / 改写后 query，bad case 可定位到改写层。

## 关键细节 / 易错点
- 追问"改写引入错误怎么办"：改写 prompt 约束"不得新增事实"；保留原 query 双路召回做安全网。
- 追问"多轮对话改写"：把最近几轮历史 + 当前 query 一起给 LLM 改写成独立完整 query。
