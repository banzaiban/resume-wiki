# 文本分块（Chunking）策略

> tags: rag, chunking, 递归分割, overlap, 多模态入库
> weight: 1
> updated: 2026-07-30

## 核心结论
常用策略：固定窗口切、按段落/语义切、递归分割（按分隔符优先级 段落→句子→词 逐级下切，保证语义完整）。overlap 一般 10%-20%。块大小看任务：太小丢上下文、太大召回不准且语义稀释。表格转 Markdown 单独成 chunk；图片先 OCR 或生成描述文本再向量化，保留位置/来源元数据。

## 展开
- **固定窗口**：按 token 数硬切，简单但会截断句子；配 overlap 缓解。
- **递归分割**（LangChain RecursiveCharacterTextSplitter 的思路）：给定分隔符优先级（`\n\n` 段落 → `\n` → 句号 → 空格），先用最高级分隔符切，超长的块再用下一级递归切——尽量在自然语义边界断开。
- **语义分块**：按相邻句子 embedding 相似度突变点切分，语义最完整但成本高。
- **结构感知**：Markdown/HTML 按标题层级切，块里带上标题路径（面包屑）增强可检索性。
- **overlap 的作用**：跨块边界的信息在两个块里都完整出现，防止关键句被切断后两边都检索不到。
- **多模态入库**：
  - 表格：转 Markdown/CSV 整表独立成 chunk（切碎会破坏行列对应），大表可按行分组+重复表头；
  - 图片：OCR 提文字，或用多模态模型生成描述文本做向量；保留图片引用位置，命中后可回给原图；
  - PDF：解析时保留标题层级、页码等元数据。
- 块大小经验值：QA 类 200-500 token；摘要类可更大；配合父子块策略（检索小块、返回父块大上下文）兼顾精度和完整性。

## 关键细节 / 易错点
- 追问"chunk 大小怎么定"：没有万能值，用检索评测（recall@k）对比几组配置实测。
- 追问"为什么表格不能按普通文本切"：行列语义靠对齐关系，切断后单元格失去表头上下文。
- 父子块 / small-to-big 是高频加分项：小块向量准，命中后扩展到父块给 LLM 完整上下文。
