# Human-in-the-loop：高敏感操作的人工干预

> tags: llm-agent, human-in-the-loop, 审批, 安全, interrupt
> weight: 1
> updated: 2026-08-04

## 核心结论
支付、转账、删除等高敏感操作不能直接让 Agent 自动执行：动作风险分级，高风险动作前挂起（interrupt）→ 推送人审批（展示动作 + 参数）→ 人确认/修改/拒绝 → 恢复执行或终止。实现靠 checkpoint（挂起时状态可恢复）+ 审批通道 + 审计日志。

## 展开
- **风险分级**：只读操作放行；可逆写操作（草稿）自动但记录；不可逆/资金相关（支付、群发、删除）强制人工。
- **干预流程**：
  1. Agent 执行到高风险节点 → 状态 checkpoint 落库，流程挂起；
  2. 通知审批人（前端弹窗/IM 卡片）：展示要执行的动作、参数、理由、影响面；
  3. 审批结果回传：批准（原样或改参）→ 从 checkpoint 恢复续跑；拒绝 → 路由到降级/终止分支；
  4. 超时策略：超时未审批按拒绝处理或升级提醒。
- **工程要点**：审批操作本身幂等（重复批准不重复执行）；全链路审计日志（谁、何时、批了什么、模型当时的上下文摘要）满足合规；LangGraph 的 interrupt + checkpointer 是参考实现。
- 设计权衡：审批点太多用户疲劳 → 只对不可逆动作卡点，可逆动作事后可撤销代替事前审批。

## 关键细节 / 易错点
- 追问"怎么防止模型绕过审批"：审批是 Harness 层硬控制（工具标记敏感级别，调度时强制拦截），不是 prompt 约定——prompt 约束可被越狱，机制约束不能。
- 追问"批量高危操作"：逐条审批不可行 → 批量预审（人审规则/样本）+ 执行中实时风控拦截。
