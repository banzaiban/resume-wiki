# Agent Memory 模块设计（三层记忆）

> tags: llm-agent, memory, 短期记忆, 长期记忆, redis, 向量化
> weight: 1
> updated: 2026-07-30

## 核心结论
记忆分三层：短期=最近对话原文（Redis，会话级 TTL）；中期=对话摘要向量化（向量库，按时间衰减加权检索）；长期=用户画像宽表（结构化偏好/事实）。写入异步落盘，定时任务合并摘要、淘汰过期内容。

## 展开
- **短期记忆**：最近 N 轮对话原文，放 Redis（key: session_id），读写在请求主链路，随上下文窗口直接拼进 prompt。会话结束或 TTL 过期即清。
- **中期记忆**：会话/片段摘要（LLM 生成），向量化后存向量库。检索时按 query 相似度召回，打分带**时间衰减因子**（越久权重越低）。解决"上周聊过的事"这类跨会话引用。
- **长期记忆**：稳定的用户画像——偏好、身份事实、历史行为统计，结构化宽表（MySQL/HBase）。由离线任务从中期记忆中抽取沉淀。
- **写入路径**：异步（消息队列/后台任务），不阻塞对话响应。定时任务做：多条摘要合并去重、过期淘汰、冲突消解（新事实覆盖旧事实）。
- **读取路径**：请求时并行取三层——短期直接拼、中期向量检索 top-k、长期画像取相关字段，组装进 system prompt 或专门的 memory 段。
- **表结构**：三层大体一致：user_id、session_id、type（原文/摘要/画像）、content、embedding、created_at/expire_at。

## 关键细节 / 易错点
- 记忆冲突：用户说"我不吃辣"后来又说"最近爱吃辣"——需要时间戳优先或让 LLM 做冲突消解。
- 记忆污染：错误信息一旦写入会持续影响后续对话，写入前要过质量门槛（置信度/来源校验）。
- 隐私合规：用户数据要可删除（右被遗忘），画像字段脱敏。
- 追问"为什么摘要而不是存原文"：原文太长、检索噪声大；摘要压缩信息密度，但要接受有损。
- 追问"时间衰减怎么实现"：score = 相似度 × e^(-λ·Δt)，λ 控制衰减速度；或分桶（近 7 天/30 天/更久）加权。
