# 提高工具调用准确率

> tags: llm-agent, tool-call, function-calling, json-schema, few-shot
> weight: 1
> updated: 2026-07-30

## 核心结论
四个抓手：① 工具描述写细（用途、适用/不适用场景、每个参数含义与取值范围）；② 给 few-shot 示例（尤其易混工具的对比样例）；③ 输出强制 JSON Schema / function calling 约束；④ 参数校验 + 失败自动重试（把校验错误回传让模型改）。

## 展开
- **工具描述是最高杠杆**：模型选工具本质是语义匹配，描述里要写清"什么时候用它、什么时候不要用它"。易混工具（如"搜索订单" vs "查询物流"）要显式写出边界。
- **参数设计**：参数越少越简单越准；枚举类型优于自由文本；必填/选填标清楚；给默认值减少模型负担。
- **工具数量控制**：工具太多（>20）选择准确率明显下降 → 分组 + 工具检索（先按 query 召回候选工具子集再给模型）。
- **结构化约束**：用 function calling / JSON mode，从生成层面保证格式合法，比事后解析可靠。
- **校验与重试**：JSON Schema 校验参数，不通过就把具体错误（缺哪个字段、值不合法）回传给模型重生成，不打到下游。
- **统一接口层**：所有外部 API 包一层网关（统一鉴权、超时、重试、日志、错误码），模型侧看到的是干净一致的工具视图。
- **评测**：建工具调用评测集，指标 = 工具选择准确率 + 参数正确率，改动前后回归。

## 关键细节 / 易错点
- 典型失败模式：选对工具但参数抽错（时间、ID 类最常见）→ 在描述里给格式示例（如 "date: YYYY-MM-DD"）。
- 追问"工具很多怎么办"：工具检索/分层路由（先选类别再选具体工具）。
- 追问"模型幻觉出不存在的工具"：白名单校验 + 结构化输出约束，出现即拦截并回传可用工具列表。
