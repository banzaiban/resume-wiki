# 意图识别优化（小模型分类 + 规则 + 大模型兜底）

> weight: 2
> wrong: 1
> updated: 2026-07-30

## 核心结论
经典三级级联：BERT 等小模型微调做主分类（快、便宜、可控）→ 规则补漏（高频硬 case 直接命中）→ 置信度低的丢给大模型二次判断。上线后靠 bad case 定期回流迭代。

## 展开
- **为什么不全用大模型**：意图分类 QPS 高、延迟敏感，小模型（BERT/RoBERTa 微调）推理几十 ms、成本低、输出稳定可控；大模型只处理小模型置信度低于阈值的长尾（通常 <10% 流量）。
- **数据**：收集线上真实 query 做标注（而非造数据），保证分布一致；类别不均衡时做重采样或 focal loss。
- **规则层**的位置：放在模型前（正则/关键词精确命中高频意图，短路返回）或模型后（修正已知的系统性误判）。规则是补丁不是主体，要定期清理。
- **置信度路由**：softmax 最大概率 < 阈值 → 走大模型（few-shot prompt 里带上候选意图和例子）。阈值定法：验证集上把阈值 t 从低到高扫描，每个 t 记两个数——覆盖率（置信度 ≥ t、小模型自己拍板的占比）和该部分的准确率；t 越高准确率越高但覆盖越低、转大模型流量（成本）越大，按"准确率达标 + 成本预算"选平衡点（如 t=0.8 时覆盖 88%、准确率 96%、12% 流量走大模型）。
- **概率分布怎么来的**：BERT 的 `[CLS]` 最后一层 hidden state（768 维）→ Linear 分类头 → logits（每意图一个分数）→ 推理时自己 `softmax(logits)` 得到概率分布，`max(probs)` 即置信度。部署到 ONNX/Triton 后服务返回 logits，同样后处理。
- **置信度校准**：神经网络普遍过自信（softmax 概率 ≠ 真实正确率），可用 temperature scaling 校准（logits 除以验证集上学出的 T 再 softmax）——这也是阈值必须验证集实测的原因。除 max prob 外的不确定性信号：top1−top2 margin（差距小 = 意图纠结）、熵。
- **迭代闭环**：线上采样 + bad case 回流 → 补标 → 定期重训。监控意图分布漂移（新业务上线、用户习惯变化）。

## 关键细节 / 易错点
- 追问"多意图/意图嵌套怎么办"：多标签分类，或让大模型输出结构化多意图。
- 追问"新意图冷启动"：没数据时先用大模型 + few-shot 顶着，攒够数据再蒸馏到小模型。
- 追问"为什么不用 embedding 相似度匹配"：可以做召回但边界模糊的类别区分度不够，微调分类头更准。
- 大模型二次判断的输出要约束成枚举（给定意图列表选一个），避免自由发挥。
