# Agent 轨迹评估与运行监控（死循环检测）

> tags: llm-agent, observability, 轨迹评估, llm-as-judge, 死循环, 监控
> weight: 2
> updated: 2026-08-04

## 核心结论
Agent 质量靠轨迹（trace）评估：记录每步 thought/action/observation，用 LLM-as-judge 按步打分（工具选对没、参数对没、是否推进任务），中间节点有效性可用"该步前后任务成功率差/信息增益"量化归因。死循环靠规则检测（相同 tool+args 重复 N 次、步数上限、状态无进展）触发熔断降级。

## 展开
- **轨迹记录**：每次运行落完整 trace（trace_id、每步输入输出、工具调用参数与结果、耗时、token），是评估与排障的数据基础（LangSmith/Langfuse 或自研）。
- **自动评估轨迹**：
  1. 步骤级：LLM judge 对照任务目标检查每步合理性（工具选择、参数、观察利用）；
  2. 结果级：最终答案对不对（有答案集可自动比对）；
  3. 中间节点有效性量化：消融法——跳过/替换某中间节点看端到端成功率变化，贡献即该节点价值；或看该步带来的信息增益（新事实数、子目标完成数）。
- **死循环监控**：
  1. 检测：相同 (tool, args) 连续重复 ≥N 次；总步数/时长超预算；状态哈希连续多步无变化；
  2. 处置：熔断——终止当前循环，把"已卡死"作为 observation 回传让模型换策略，仍失败则降级（直接回答已有信息/转人工）；
  3. 告警：循环率、平均步数、单会话 token 进监控大盘，突增告警。
- 指标看板：任务成功率、平均步数、工具失败率、循环率、P95 延迟、单会话成本。

## 关键细节 / 易错点
- 追问"LLM judge 可信吗"：抽样人工校准 judge 准确率；客观信号（测试通过、schema 校验）优先于主观打分。
- 追问"怎么防监控本身拖慢主链路"：轨迹异步落盘，评估离线跑。
