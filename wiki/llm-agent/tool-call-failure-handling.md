# Agent 工具调用失败处理

> tags: llm-agent, tool-call, 重试, 降级, 容错, 可观测
> weight: 3
> updated: 2026-08-04

## 核心结论
四层：重试（指数退避+抖动）→ 降级（备用工具/兜底话术/静态答案）→ 监控告警（打点、连续失败告警）→ 让模型自愈（把错误信息回填给 LLM 让它换参数或换工具重试）。

## 展开
1. **重试**：区分错误类型——超时/限流/5xx 可重试，参数错误/4xx 不该盲目重试。指数退避 + jitter 防止惊群。设置重试上限（通常 2-3 次）。
2. **降级**：主工具挂 → 备用工具（如主搜索挂切备用搜索）；都挂 → 兜底话术或缓存的静态答案；保证"有损可用"优于直接报错。
3. **可观测**：每次调用打点（工具名、耗时、状态码、trace_id），失败率/连续失败触发告警；熔断器（circuit breaker）在连续失败后直接短路，避免雪崩。
4. **模型侧自愈**（LLM 特有）：把工具返回的错误消息作为 observation 回传给模型，模型可修正参数重试、换用其他工具、或向用户澄清。这是 Agent 区别于传统 RPC 容错的关键一环。
5. **参数校验前置**：工具入参用 JSON Schema 校验，模型给的参数不合法时直接返回结构化错误让模型改，不真正打到下游。

## 关键细节 / 易错点
- 追问"模型调工具产生参数幻觉/语法错误，有哪些自动修正手段"：schema 校验不通过 → 把缺失/非法字段的具体错误回传模型重生成；JSON 语法错误先程序化修复（jsonrepair、正则提取代码块）；枚举类参数做模糊匹配纠正；连续修正失败则降级并记录 bad case。
- 追问"多工具并发部分成功部分失败，怎么汇总给模型"：每个工具结果独立封装（tool_call_id + status + result/error），失败项附简要可行动的错误说明，一并回传；模型据此决定重试失败项、换工具、或基于部分结果作答并在回复中说明缺失。
- 重试要考虑**幂等性**：非幂等工具（下单、发消息）不能自动重试，需去重键或确认机制。
- 错误信息回传给模型时要**简洁且可行动**（说明缺哪个参数/什么原因），冗长堆栈会污染上下文。
- 超时预算要分层：单工具超时 < 单步超时 < 整个会话超时。
- 追问"怎么防止模型无限重试循环"：限制单会话工具调用次数/同一工具连续失败次数，超限强制降级。
