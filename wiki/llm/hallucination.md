# 幻觉的原因与缓解

> tags: llm, hallucination, 幻觉, RAG, 置信度
> weight: 3
> updated: 2026-08-04

## 核心结论
原因：训练数据噪声/知识缺失或过期、下一 token 预测的本质（流畅优先于真实）、解码采样随机性、缺乏外部知识接地、RLHF 讨好倾向。缓解：检索增强（RAG 接地）、prompt 约束（只依据给定材料、不知道就说不知道）、降低 temperature、置信度过滤、输出后校验（引用核对/自一致性/事实核查）。

## 展开
**幻觉类型**（先分类再谈缓解，面试常考"有哪些类型"）
1. 事实性幻觉：与世界知识矛盾（张冠李戴、编造文献/数据）。
2. 忠实性幻觉：与给定输入矛盾——RAG 里不依据检索内容、总结时歪曲原文。
3. 指令不遵循：格式/约束被无视（要求 JSON 输出了散文、要求"不知道就说不知道"却硬答）。

**原因分层**
1. 数据层：训练语料含错误/矛盾/过时信息；长尾知识覆盖稀疏。
2. 模型层：LM 目标是预测最可能的下一 token，不是保证事实；模型没有"我不知道"的显式机制，倾向编一个流畅答案。
3. 解码层：temperature/top-p 采样引入随机性；beam search 也可能放大局部流畅但整体错误的路径。
4. 对齐层：RLHF 奖励"有帮助的样子"，可能强化自信但错误的回答。

**缓解分层**
1. 输入侧：RAG 提供权威上下文；prompt 明确"仅根据以下内容回答，未提及则回答不知道"。
2. 解码侧：事实类任务低 temperature；约束解码（枚举/JSON Schema）。
3. 输出侧：要求带引用并程序化核对引用真实存在；self-consistency（多次采样取一致答案）；用另一个模型/规则做事实校验；置信度过滤（低置信转人工或拒答）。
4. 模型侧：领域微调、RLHF 中加入诚实性奖励、DPO 惩罚编造。

## 关键细节 / 易错点
- RAG 不能根治幻觉：检索错/不全时模型仍会补脑；且模型可能忽略给定上下文用参数知识回答（context-faithfulness 问题）。
- 追问"怎么量化幻觉"：忠实度评测（答案与给定上下文的一致性，LLM-as-judge 或 NLI 模型）、事实性基准（TruthfulQA 等）。
- 追问"业务上怎么兜底"：高风险场景（医疗/金融）强制引用+置信度阈值+人工审核链路。
