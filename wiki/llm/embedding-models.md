# Embedding 向量与模型选型

> tags: llm, embedding, BGE, M3E, 语义向量, 相似度
> weight: 3
> updated: 2026-08-04

## 核心结论
Embedding 把文本映射为稠密向量表示语义，相似语义 → 向量空间距离近（余弦相似度）。常见开源中文模型：BGE（BERT 架构，输出 768/1024 维，bge-m3 支持多语言+稀疏检索）、M3E（BERT-like，768 维，多阶段训练）。选型看 MTEB/C-MTEB 榜单 + 自己业务数据实测。

## 展开
- 训练方式：对比学习（正负样本对，InfoNCE loss），让相关对拉近、无关对推远；BGE 系用大规模弱监督对 + 高质量标注对多阶段训练。
- 使用要点：
  - 查询和文档可用不同指令前缀（BGE 的 "为这个句子生成表示以用于检索相关文章"），检索任务加 instruction 会提点；
  - 归一化后用余弦相似度（等价内积）；
  - 维度权衡：越高表达越强但存储/检索开销越大，Matryoshka embedding 可截断降维。
- 局限：单向量压缩长文档有损（所以要 chunk）；对否定、数字、精确匹配弱（所以要混合 BM25）；领域外效果下降（可微调）。
- 微调场景:业务术语/私有语料检索差时，用业务标注对(query, 正例, 难负例)微调，难负例挖掘是关键。

## 关键细节 / 易错点
- 追问"垂域 embedding 语义偏移，除混合检索和 Reranker 外还有什么办法"：① 领域语料对比微调（难负例挖掘是关键）；② 检索时加领域指令前缀；③ 领域同义词表/术语库做 query 扩展；④ 元数据/标签过滤缩小候选空间；⑤ 换用在目标领域表现好的模型（C-MTEB 分领域榜单 + 业务实测）。
- 追问"embedding 对数字不敏感（公差值/型号怎么保证召回）"：数值扰动在向量空间里几乎无差异，单靠向量召回不可靠——把数值字段抽出来做**标量过滤/范围查询**（Milvus 支持标量+向量混合检索）、单位与格式归一化、精确数值匹配走 BM25/结构化查询，最后 prompt 里让模型对数值二次核对。
- 追问"embedding 相似 ≠ 相关"：相似度高可能只是主题相近而非能回答问题，这正是需要 reranker 的原因。
- 追问"为什么 chunk 不能太大"：单向量语义稀释，长文里多主题被平均掉。
- 追问"和 LLM 的 embedding 层什么关系"：LLM 输入 embedding 是 token 级查表，检索 embedding 是句/段级语义表示，训练目标不同。
