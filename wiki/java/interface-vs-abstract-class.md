# 接口与抽象类的区别及面向对象设计

> tags: java, oop, interface, abstract-class, 设计
> weight: 1
> updated: 2026-07-30

## 核心结论
接口定义**能做什么**（行为契约），支持多实现、无状态（Java 8 后可有 default 方法但仍无实例字段）；抽象类定义**是什么**（is-a 关系），可有成员变量和具体方法，用于共享代码，只能单继承。需要多重能力组合 → 接口；需要复用状态和模板逻辑 → 抽象类。

## 展开
**对比**
| 维度 | 接口 | 抽象类 |
|---|---|---|
| 语义 | can-do（能力） | is-a（身份） |
| 继承 | 可实现多个 | 只能单继承 |
| 字段 | 只能 public static final 常量 | 可有任意实例字段 |
| 方法 | 抽象 + default/static（Java 8+） | 抽象 + 具体 |
| 构造器 | 无 | 有（供子类调用） |

**经典设计题：动物类体系**
- 顶层 `Animal` 抽象类：放共有状态（name、age）和模板方法（eat、sleep 的默认实现），`abstract void makeSound()` 强制子类实现。
- 能力用接口：`Flyable`、`Swimmable`。Cat/Dog 继承 Animal；鱼实现 Swimmable；乌龟只继承 Animal（不需要多余接口——不要给不具备的能力硬塞接口，这是接口隔离原则）。
- **鸭子能飞能游**：`class Duck extends Animal implements Flyable, Swimmable`。共有实现（如通用飞行姿态）可放接口的 default 方法或抽象类；鸭子的具体飞法自己 override。
- 进一步优化：如果飞行方式会变化（鸭子飞、火箭式飞、不会飞），用**策略模式**把 FlyBehavior 组合进来（《Head First 设计模式》的经典例子），比继承更灵活——"组合优于继承"。

## 关键细节 / 易错点
- 面试答这题要主动说出**组合优于继承**和**接口隔离原则**，只答语法区别层次不够。
- Java 8 default 方法让接口能带实现，但仍不能有实例状态——这是与抽象类的本质分界。
- 多个接口有同名 default 方法时必须手动 override 解决冲突（菱形问题）。
- 追问"什么时候用抽象类"：多个子类有大量重复代码/需要模板方法模式定义算法骨架时。

## 关联
- 常见追问链：语法区别 → 什么时候用哪个 → 动物类怎么设计 → 鸭子多能力 → 组合优于继承/策略模式
